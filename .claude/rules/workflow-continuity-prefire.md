# Workflow Continuity: Pre-Fire Checks

Moved verbatim from `.claude/rules/workflow-continuity.md` § Post-Plan. The core file keeps the decision to fire and points here.

## Matrix check

- **Matrix check first.** With a plan, `git add -A` and run `bin/lib/plan-matrix-assertions <plan> <(git diff --cached origin/master)`. Write the test for each `UNREALISED-ASSERTION` row and rerun; if you cannot, do not fire. No plan: skip.

## Prefire verification

`bin/post-plan-now` runs `bin/lib/prefire-verify` (the plan's post-impl CLI matrix rows that run locally, then PHPUnit on the tests mapped to the changed files) and exits 9 until both stages pass on the current tree. Matrix rows that `row_runs_in_ci` sends to CI, and the Executable Mutations rows, run in the required `Plan checks` CI job instead (ADR-0244). A matrix row whose whole command is one of six whole-suite runs (`vendor/bin/phpunit`, `composer run analyse` and the four other forms listed in `bin/lib/prefire-verify`), alone or after `cd ibl5 &&`, is skipped with a `skipped, CI covers full-suite runs` line, because CI runs those suites on every push. A row with a filter, a path or a chained command still runs. Exit 9 means the gate refused the tree: fix the check it names. Exit 10 means the gate could not run (Docker or the DB is down, or a prerequisite is missing): fix the environment and rerun, and do not hunt for a failing check. CI's required check `Infection PHP (per-PR diff)` gates mutation score. Run it first with `--plan <plan> --stage matrix`, then `phpunit`, one foreground call each. An implementer may also run `--stage exec-mutations` by hand to check a mutation row early. The fire point does not run it. A pass is cached by tree hash. A changed file with no mapped test runs nothing locally and defers to CI, which runs the full suite on every push. That covers a migration, a script in the ibl5 bin directory, a class that no test names, a deleted source or test file, a shared base class, a PHPStan rule fixture, a shared test helper, and the PHPUnit config, bootstrap and composer files. The log prints one `phpunit deferred to CI:` line per deferred file, and a diff with only deferred files reports `phpunit mode: skipped` and writes no pass record. A selector error, such as an unresolvable base or a failed diff, runs the full suite, and `PREFIRE_PHPUNIT_FULL=1` forces it. With no plan, the matrix stage skips. A human may bypass with `--skip-verify=<reason>`; it is logged and refused under `CLAUDE_HEADLESS`.

The `pytest` stage runs after `phpunit` in the default `all` order. It maps changed post-plan harness files to test files under `tools/postplan-harness/tests/` and runs only those, serially, with explicit file arguments and `-p no:xdist`. A changed `test_*.py` runs itself. A changed harness module runs the test files that import it. A changed CI trigger script, for example `bin/lib/pr-armable.sh`, runs the test files that name its basename. The stage never runs the whole harness suite. A shared input (`conftest.py`, `parallel_default.py`, any other file under `tests/`, `harness/state.py`), a file with no mapped test, an unresolvable base, and a selection over 25 test files each print a `pytest deferred to CI:` line, because the Python tests workflow runs the whole suite on every PR that touches those paths. A tree with no harness trigger path prints `pytest mode: skipped`. A missing `python3` or pytest exits 3, and a red selected test exits 1. Decision: `ibl5/docs/decisions/0249-prefire-pytest-stage.md`.

The `phases` stage runs first in the default `all` order. It runs `python3 -m harness.conformance --phases` on the plan and the working tree, so committed, uncommitted and untracked paths all count. It exits 1 when a plan phase cites repo files and the diff touches none of them, the same `MISSING-PHASE:` item post-plan Phase 5.0 reports. When that phase's work already landed on master, add a `**No diff:** landed on master in <sha> (#PR)` line to the phase body, or list the phase under `## Out of Scope`. A held plan with phases marked this way prints a `REMINDER:` line. Re-derive `hold_trigger:` from what the final diff touches before you fire. The reminder never fails the stage. With no plan, the stage skips. A conformance run that cannot read the plan, or a missing harness, exits 3, which `bin/post-plan-now` reports as exit 10.
