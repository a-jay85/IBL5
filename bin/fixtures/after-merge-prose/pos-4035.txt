## Merge digest

**What changed:** The owner can now approve a held PR, or ask for a fix first, by pressing a button in the Discord DM, and a Mac job turns that press into a `bin/owner-approve` run.

**Why:** The owner wants to approve a held PR from the phone in one tap, without going back to a terminal.

**Watch:** `bin/lib/launchd-expected-jobs.sh` now expects `com.ibl5.approve-click-tick`, so the launchd health check reports it missing until the owner runs `bin/approve-click-cron-setup --install`. When a button DM fails to send, `mintToken` has already retired that PR's older button, so the owner falls back to the CLI.

**Touches:** bin/approve-click-tick, bin/approve-click-cron-setup, bin/post-plan-fleet, bin/test-plan-review-seam, bin/lib/, bin/fixtures/, ibl5/IBLbot/src/, ibl5/IBLbot/README.approve-buttons.md, ibl5/docs/decisions/0262-discord-approve-buttons.md, .gitleaks.toml

**Machine-authored fixes:** Earlier review-thread commits built the button path from `$ROOT` and widened `CONTROL_RE` to C1 control characters. This run's Phase 6.5 has not run.

## Summary
- Adds Approve and Fix first button handling to IBLbot in `ibl5/IBLbot/src/interactions/approve-buttons.ts`. Only the configured owner id can press. Fix first opens a modal for a condition of up to 300 characters with no control characters. Each press is recorded once per token, and a press on an expired, used or replaced token gets an ephemeral refusal.
- Wires the button and modal handlers into `ibl5/IBLbot/src/index.ts` under the `approve_` and `approve_cond_` custom id prefixes.
- Adds `bin/approve-click-tick`, a Mac-side poller. It lists pending presses over the existing ssh route and claims each one at most once, using marker files in a local ledger. It re-checks the actor, the press age, the PR state and the live head SHA, and fails closed when `gh` fails. It then starts a detached `bin/owner-approve` run, passing the condition as one argv element so shell metacharacters stay literal. It DMs the outcome, and DMs about a press that was claimed but never ran. It exits 3 under `CLAUDE_HEADLESS`, except `--send-button`.
- Adds `bin/approve-click-cron-setup`, which prints, installs or removes a launchd agent that runs the poller every 180 seconds. The agent points at the main checkout.
- `bin/post-plan-fleet` now sends the button DM after the held text DM. A failed button send never suppresses the text DM.
- `bin/test-plan-review-seam` gains drift checks for the three approve routes in `express.ts` and for the owner id pinned in both `bin/approve-click-tick` and `bin/discord-dm`. It also gains stubbed ssh, gh, owner-approve and discord-dm cases for the poller. They cover a valid press, a moved head, duplicate ticks, metacharacters in the condition, the headless guard, a crash mid-run, the condition cap, control characters, a wrong or numeric actor, a 409 claim, closed PRs, the plist and the post-plan-fleet ordering.
- Adds vitest tests for the button and modal handlers and for the click store, plus `ibl5/IBLbot/README.approve-buttons.md`, a prod and Mac runbook.
- The diff shown was truncated, so this summary covers only the visible part. Nothing here changes what a league GM sees. It is owner and dev tooling.
- The launchd agent is not installed by merging. The owner runs `bin/approve-click-cron-setup --install` once on the Mac after merge.

**Merge danger:** Door: two-way · Blast radius: site-wide · Why: Adds new bot routes and Mac scripts; nothing runs until the owner deploys the bot and installs the agent, and a revert removes the code.
**How to revert:** `git revert <merge-sha>`, then run `bin/approve-click-cron-setup --uninstall` on the Mac if the agent was installed, and `pm2 restart iblbot` on prod.
