## Summary
- Adds close notices to `bin/bug-pipeline-tick`. Each tick checks tracked issues. When one is closed, the bot posts one Discord message that mentions the reporter. The text is fixed words plus the issue URL: fixed, not planned, duplicate, or plain closed. No issue title, body or comment is ever sent, because the repo is now public.
- Checks at most 25 tracked issues per tick, so a tick makes at most 25 gh issue reads. The tick saves the last issue number it read in `~/.claude/logs/bug-pipeline-notice-cursor`. The next tick passes it as `--after` to `issue-notice-pending.php` and reads the next 25. A page shorter than 25 sends the cursor back to 0. With N pending issues, each one gets checked at least once every ceil(N/25)+1 ticks (the +1 is an empty tick that only resets the cursor when N is a multiple of 25), so issues that stay open cannot hide the ones after them. `close_notice_pages_one_window_per_tick` in `bin/test-bug-pipeline-tick` covers this.
- Posts at most once per issue. A row goes pending to claimed before the post and to notified after it. A failed post is released and retried, and a row that fails repeatedly is marked failed. A crash between claim and mark leaves the row claimed, and the tick logs it as stuck every run.
- Registers each newly filed issue with the notice table from `file_and_close_row`, saving the reporter, channel, thread and original message ids.
- Adds a migration that creates the `ibl_bug_issue_notices` table, keyed by the public-repo issue number. It also has the legacy `ibl5-bugs` number and the notice state. The table is added to `bin/db-sync-preserve-tables.txt` so a prod sync keeps it.
- Adds the one-off, owner-run `bin/bug-issues-migrate`. It moves the 29 issues from `a-jay85/ibl5-bugs` to `a-jay85/IBL5`, rewrites the old links in the bot's Discord messages, and records the old-to-new map in the DB. Dry-run is the default. `--live` needs a typed confirmation and refuses under `CLAUDE_HEADLESS`. It can resume from a state file.
- Points the default issue repo at `a-jay85/IBL5` in `bin/bug-pipeline-tick`, `bin/bug-pipeline-cron-setup` and the cron plist golden file. `--bootstrap-issues` now only views the repo and exits with an error if it is missing. If `gh repo view` fails for another reason (a network error, say), it warns and keeps going. It never creates a repo.
- Audit, no code change: `ship_via_cron` hands off to `bin/post-plan-now` and builds no issue reference. `$REPO` at `bin/lib/burndown.sh:96` is set nowhere in the burndown files.
- Adds `bpgh_issue_close_state`, which reads only the issue state and close reason.
- Adds tests: `bin/test-bug-issues-migrate` (registered in `.github/workflows/harness-legs.txt`), stubs for the notice scripts and the post-with-mention call, and a repository integration test.
- Updates the `bugreports` row in the reset-ready skill to look for `gm-reported` issues in `a-jay85/IBL5`.
- The migrate script is not run by this change. The owner runs it by hand.
